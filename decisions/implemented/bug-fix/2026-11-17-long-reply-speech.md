# Decision: озвучивать только длинные ответы беседы и читать их целиком

Status: implemented

## Problem

Голосовой режим читал всё подряд. `voice.autoSpeakChat` по умолчанию был включён, поэтому при `voice.enabled: true` озвучивались короткие ответы, смена уровня, приветствия, ошибки и реплики кормления/игры. Пользователь не просил говорить эти фразы, и голос включался без предупреждения.

Длинные ответы обрывались ближе к концу. Клиентский `speak()` прогонял текст через `normalizeVoiceText()`, который режет строку до `VOICE_TEXT_MAX` (300 символов), а серверный `/voice` повторно применял тот же предел. Всё, что не помещалось в 300 символов, не доходило до TTS.

## Decision

- Авточтение длинных ответов — явный opt-in. `voice.autoSpeakChat` по умолчанию `false`; `voice.minSpeakChars` задаёт минимальную длину очищенного ответа (по умолчанию 200 символов, `0` — любой непустой ответ). `shouldSpeakReply()` требует одновременно `voice.enabled`, `voice.autoSpeakChat` и числовой порог. Конфиг без `minSpeakChars` (записанный, когда авточтение было включено по умолчанию) считается выключенным, пока пользователь не включит режим заново.
- Автоматически озвучиваются только ответы беседы, прошедшие порог. Кормление, игра, смена уровня, welcome/celebrate/error/disappointed и случайная болтовня показывают облачко, но не вызывают `speak()`.
- Длинный ответ читается целиком. Клиент очищает текст и режет его на фрагменты не длиннее `VOICE_TEXT_MAX` по границам предложений, затем клауз, тире и слов (`splitSpeechChunks()`); фрагменты воспроизводятся последовательно. `speechPending` остаётся `true` до конца последнего фрагмента, поэтому облачко, `finishChatWhenIdle()` и возврат в режим разговора ждут полного прочтения.
- Следующий фрагмент готовится заранее: пока играет фрагмент N, запрос синтеза для N+1 уже выполняется. Первый фрагмент по-прежнему стримится PCM, чтобы звук начинался до конца синтеза; подготовленные фрагменты приходят готовым аудио и играют без паузы на ожидание TTS. Весь ответ использует один `AbortSignal`, поэтому остановка отменяет и уже начатую подготовку.
- Облачко ответа не исчезает во время чтения: таймер показа продлевается, пока `speechPending` относится к этому облачку, а после окончания речи ему заново выдаётся полная длительность чтения. Событийные реплики (`welcome`, `celebrate`, `error`, `disappointed`, `levelUp`) в это время не показываются, чтобы не заменять читаемый ответ.
- Остановка (закрытие чата, Esc, смена настроек, новый ответ) инвалидирует сессию речи: поздние `onend`/сетевые ответы не трогают состояние следующей реплики. Отмена не показывает ошибку.
- Серверный предел 300 символов на один TTS-запрос сохранён: длинный ответ обслуживается несколькими запросами, а не повышением лимита.
- Настройки показывают переключатель «Читать длинные ответы» и числовой «Порог чтения».

## Alternatives considered

- Поднять `VOICE_TEXT_MAX`: длинный один запрос повышает риск таймаута и лимитов провайдера, а ответ всё равно обрезается за новым пределом.
- Оставить `autoSpeakChat: true` и просто фильтровать короткие ответы: авточтение остаётся включённым по умолчанию и продолжает говорить без запроса.
- Читать только ответы на сообщения с `?`: длинные ответы на просьбы «расскажи…» остались бы без голоса.
- Озвучивать события тише или короче: это всё ещё непрошеная речь.

## Consequences

- Короткие реплики и события молчат; длинные ответы читаются до конца. Длинный ответ требует нескольких последовательных запросов TTS, поэтому пауза между фрагментами и сброс интонации на границе фрагмента возможны.
- Подготовка следующего фрагмента идёт параллельно с проигрыванием текущего: TTS-провайдер должен допускать два одновременных запроса. Готовое аудио следующего фрагмента хранится в памяти до начала его проигрывания.
- Смена настроек голоса требует перезапуска web-хоста для Node-половины (схема и значения по умолчанию) и обновления `lib/client.js` с перезагрузкой страницы для клиентской части.
- `normalizeVoiceText()` остаётся серверным ограничителем одного запроса; клиент больше не использует его для обрезки полного ответа.
